# 普通手牌落点与刷新顺序

本批修复普通单位部署：原入口直接 Move，未留出插入空位，且移动回调发生时剩余手牌尚未重排；目的地稀疏或发生槽位冲突时还会受到 CardId 排序影响。现在先按物理位置留空插入，再刷新原手牌和目的地，最后执行移动回调。默认根动作仍使用数量作为默认落点，两条自动出牌路径仍使用槽位 0。

权威依据是解包后的 BP_BaseCard、BP_PlayerMoves、BP_CardFunctions 原始解析语句：PlaceHandCard 将落点传入视觉和非视觉位置队列；PlayCardFromHand i=1988 调用 CardLocationMoved；后者 i=215 插入，i=348 刷新，i=578 触发移动事件。InjectCardIntoLocation i=54 创建空位、i=95 设置位置；空位判断使用 >=。WaitOnBoard 的显示预留不作为规则槽位实现。三个原始资产的 uasset/uexp 均与新 FModel 导出逐字节相同，这不证明整个客户端版本关联。

新增失败回归在旧实现下失败；修复后 24 个场景覆盖左右两侧、稠密/稀疏目的地、源 ID 在已有单位 ID 前后，以及默认根动作/行动内自动出牌/队列自动出牌。检查回调时与最终的手牌、总部和单位槽位，并经真实单卡 IR 执行。完整 1030 项 BotSim、49 项动作数据及 31 项模型检查通过。

固定种子 12 前缀诊断为 535 候选：107 接受、418 拒绝、10 未知；双向 1070 个引擎、7284 次前缀根动作，正反结果完全一致。前十个前缀与旧报告相同，后两个状态/候选集合不同，不能把减少八个候选当作同状态合法性改善。此诊断不使用旧回放作规则权威。

DeepSeek 仅提取位置字段及原始调用记录；主 agent 独立完成 98 项机械核对，覆盖输入函数一致、字段出现完整性和原始语句相等。规则判断、修复和发布由主 agent 完成。

仍未闭合：明确根动作落点（继续拒绝）、指令移动、完整通知字段/时机、同位置队列出牌、完整烟幕/前线生命周期、逐卡认证及可靠合法掩码。下一批优先核对普通 PlayCardFromHand 的移动通知与回执是否影响规则状态。
