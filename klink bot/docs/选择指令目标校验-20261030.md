# 训练根动作的选择指令目标校验

本批修复训练 ApplyRoot 中的两个缺口：选择型定向指令曾跳过本次具体目标检查；旧的目标标记也可能阻止本次无目标分支出牌。选择分支现在先复用已有 WhichChooseOne 实现刷新目标标记，再进行可用性查询；需要目标的指令在扣费、动作记录与效果执行前复用 CanTarget 检查指定目标。

## 权威依据与范围

直接检查游戏资产解析出的完整 CanPlayFromHand、OnPlayedFromHand 和对应 Ubergraph：

| 卡牌资产 | 分支 1 的目标条件与效果 |
|---|---|
| card_event_barrage | hasTarget 且 IsGroundUnit；造成 2 点伤害 |
| card_event_hidden_plans | hasCovert 且 IsUnit；揭示并 +1/+1 |
| card_event_refit_bia | hasTarget 且 subtype.spitfire；赋予闪击 |

三者均在 CanPlayFromHand 的 StatementIndex 0 调用 WhichChooseOne，分支 0 在 114 返回 canIt=true、185 设置 targetedCard=None；分支 1 从 201 获取指定目标。已检查的单卡谓词不限定阵营，仍须通过公共目标条件。Refit 的目标分支 GiveBlitz 位于 Ubergraph 1226。

共享目标枚举与公共门槛沿用上一批已核对的 BP_Logic.CanPlayCardFromHand、cardsCheckFunctions.CanSelectAsTarget。WhichChooseOne 复用既有原生契约实现，仅抽出共享方法；训练入口提前刷新是适配器的分支准备，不据此宣称完整客户端动作生命周期顺序已闭合。旧 public PlayCard 和 CanPlay 查询语义未改。

原始 uasset/uexp、解析文件、日志、运行输入及二进制指纹见[机器记录](../../out/training-readiness/choice-order-targets-20261030.json)。既有 WhichChooseOne 原生证据来自历史已映射版本；当前执行文件在历史 RVA 的字节不同，未重新确认当前版本的符号映射，不更新历史认证指纹，也不宣称当前客户端和全部提取资产的版本关联已闭合。

最终版本的新测试在旧 59cf0ff 生产代码上为两组失败、一组通过；修复后完整 1021 项 BotSim、49 项动作数据、31 项动作模型检查全部通过。早期夹具误将飞机作为地面单位、误把 Refit 效果写成防御增益，已按完整函数核正后重跑前后对照；错误夹具不作为缺陷证据。
