# 训练策略选择接口 v1

本批提供 `KLink.Bot.Training.ChoicePolicyAdapter`，连接既有引擎的手牌目标、牌库多候选、开发和预报回调。它是同步选牌子接口；没有改引擎、卡牌 IR、贪心策略、胜负规则或训练准入。

策略收到 `PolicyChoiceRequest`：接口版本1、观察规格 `StateEncoder.Spec`、序号、选择方、回合、触发卡ID/名字、是否可取消、只读候选快照和只读观察向量。选择方取触发卡控制方，可能不同于当前回合行动方。候选只有索引、ID、名字、攻击、防御和花费，不传可变 CardInstance 或引擎对象；相同名字/模板ID的候选仍按展示索引区分。

策略返回本次候选的索引。仅手牌目标允许 `-1`，映射到既有ID0回复；这不是未回答。其它负数、越界索引、无效选择方、重入和策略异常均报错并计入 `Faults`，不默认选第一张。宿主必须拒绝 `Faults > 0` 的整局，即使异常被VM捕获。异常后的部分执行状态不能当作可重试的原子事务。

```csharp
// engine、vectors 由宿主创建。这里只演示可重复的第一候选基线。
using var choices = new ChoicePolicyAdapter(engine, vectors, request =>
{
    if (request.Options.Count == 0 && request.CanCancel) return -1;
    return 0;
});
// 随后启动/驱动对局。每次真正调用选择钩子时同步进入策略。
// 整局结束后另检查原有执行健康条件，以及 choices.Faults == 0。
```

在对局选择开始前安装，已有选牌回调或待选队列时拒绝安装，避免覆盖回放/其它策略。释放仅移除自己仍持有的回调，不覆盖后续所有者。此接口要求单线程、同步、纯策略函数；它不是OS隔离，策略不应通过闭包访问/修改引擎。序号和索引只适用于当前同步调用，不是可长期保存的异步动作凭证。

## 已验证

4组回归覆盖双侧手牌索引/ID0取消、空手牌回复、候选快照不可变、牌库/开发/预报真实结算、同名牌索引、非法索引、回调所有权及重复释放。观察对照用不同的合成卡向量：替换对方手牌、双方牌库的隐藏卡身份不改变向量；替换己方手牌会改变向量。这个测试不等于完整的可见信息或观察充分性认证。

100组同种子完整对局，各跑默认选择与适配器第一候选：动作日志SHA、随机流、回合、胜负、VM错误/调用计数及最终观察保持。它证明这组中转没有改变基线，不说明第一候选是好策略，也不认证游戏规则。完整991项内核回归与17项准入检查通过。

## 开放边界

- 主动作接口与合法掩码尚未接入；既有NnPolicy枚举的是候选超集，不能直接称为合法动作集。
- 同步Forecast、自动/单候选内联路径没有异步暂停能力；引擎不调用钩子的路径不会产生策略请求。
- OfferedCard暂未细分牌库、开发和预报类型；现有ChooseSpawnCard签名没有这些元数据。不要靠模板ID猜测来源。
- 目前复用745维StateEncoder，尚无完整的单卡对象观察、选择记忆、已揭示信息/反制可见性或动作特征契约。
- NNTrain已接入适配器及独立Faults检查；`--sampling decision`在主策略步骤/选牌回答前采样，默认turn仍保留回合末采样。两者是左方视角价值样本，尚无动作标签/掩码。详见[决策采样](训练决策采样-20261030.md)。
- 三局Queen’s Own长对局继续作为unfinished拒绝，本批没有更改它们的策略或虚构结果。
