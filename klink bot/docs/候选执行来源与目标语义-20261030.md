# 候选执行来源与目标语义

本批完成上一批16个未知候选的来源定位，并新增指定目标效果检查。没有新增游戏规则或整卡认证，没有生成训练数据、模型或合法动作掩码。机器记录见[证据](../../out/training-readiness/action-probe-provenance-20261030.json)。

## 诊断契约

`IsolatedActionProbe` 升为 experimental-v2：逐候选增加原命令、己方源卡名、失败阶段、非信息性调用/不支持操作的计数，以及VM故障和选牌计数。根动作阶段记录相对已重建前缀的增量；start/prefix/comparison失败记录从引擎创建起的计数，由阶段字段区别。构造失败可能没有证据对象。诊断不进入策略特征，不附带敌方卡名或后继状态。

原有三态判断与信息标记名单保持一致；Unknown不等于非法。新增报告结构改变序列化契约，旧消费者需按版本处理。

## 指定目标实验

新增 `BotSim probe-targets --out <绝对路径>`，构造左右双方对称夹具，测试 `card_event_desert_rats`。夹具人为设置单位5防御，隔离观察参数转发和伤害/压制，不作为合法训练前缀或权威规则证据。

| 传入目标 | 每方观察结果 |
|---|---|
| 敌方80、81 | 返回true，CurrentTarget精确匹配；仅指定目标防御5→4并被压制 |
| 友方82 | 同样返回true，友方受到伤害及压制 |
| 0、不存在的99999 | 返回true，CurrentTarget为空，三个单位均未改变 |

两方共10个观察用例。全部无VM故障，诊断通道仅出现 `<local-ran:GetPlayFromHandDamage>` 信息标记。新增回归断言只锁定四个有效敌方目标的参数转发和实际效果，不把友方/空目标被接受固定成正确规则。

静态调用链为 `ApplyRoot → PlayCard → CanPlay → PlayCardFromHandCoreImpl → RunDeploymentEffect → CardApi → KismetVm`。`CanPlay`对该类指令检查存在可用目标，但未在此处验证传入的具体目标；不存在的ID经ById变为空目标。蓝图目标参数能到达效果体，动作接受边界仍不可靠。未凭模拟器夹具擅改规则：下一步应针对权威蓝图的明确目标谓词，补验证具体目标的路径及无副作用检查，再加入跨卡型回归。

## 验证和证据边界

全部1014项BotSim回归、49项动作数据检查、31项模型检查通过。新增两项覆盖命令/诊断增量及双侧指定目标效果。完整测试在独立工作树运行，保留主工作区原有未提交修改。

独立工作树检出产生的数据换行差异会使既有IR指纹校验失败。构建后复制主工作区同基线、已可正常加载的BotSim输出Data JSON原始字节，再以 `--no-build` 验证；未修改指纹、未绕过IR校验。机器记录绑定实际加载Data、工作树源码、二进制及日志SHA-256。

DeepSeek仅机械清点两份源码副本。主agent确认副本哈希与工作树一致，独立核对73处精确摘录；另3处多行摘录的区间少包含了下一行闭合括号，已人工核对。没有把worker的语义总结当作游戏规则权威。

本批结果仍不足以证明候选覆盖完整、指定目标全部合法、静态对象完全隔离或全部VM私有状态等价。审计矩阵继续保留输入变更导致的过期原因；不能据此估计整体还原完成率。
