# 选择回复的动作起点与停止标志

本批修复选择回复继承上一个动作 StopFurtherActions / StopAttack 的问题。回复现在在回调、额外触发和自动出牌前清除旧标志，同时重设取消通知的日志边界。手牌策略没有回答或给出不合法目标时，不启动回复动作；回复内部重新设置的标志不会被尾部清掉。

## 权威依据与边界

保存的 PlayerMoves 解析在 i8750 / i9624 开始手牌目标／选牌回复动作，再调用卡牌回调。OnlineMatch.CreateAction_InitStart 调用 SuperActionStarted；后者 i0 设置 StopFurtherActions=false，i37 设置 StopAttack=false，i74 开始处理动作。先前模拟器仅重设日志边界，未清理这两个标志。

OnlineMatch 的 SuperActionStarted、InitStart、两种选择回复 Start、PassiveEffect_Start/End、CardMarker_Start/End 共八个函数，其 bytecode、function_flags、expression_count 与新解析逐项一致。没有宣称 PlayerMoves 新旧版本完全一致。

PassiveEffect_Start 记录当前 subActions 长度并追加 passiveEffects 标记；End 根据标记和后续通知判断保留／删除。两者不调用 InitStart / SuperActionStarted，也不清空动作数组，因此不能把每次被动效果当作新的根动作。本批没有添加表现层标记模拟，也没有认证完整被动序列化。

使用 deepseek-worker 提取选定十四个 OnlineMatch 函数中的入口调用，返回十一条原始语句，主 agent 逐条精确核验。随后独立遍历完整 OnlineMatch、CardFunctions、PlayerMoves 三个解析文件，得到二十条相关调用语句。摘录本身不是全量证明；完整库存及权威函数体保存在机器报告。

## 修复与验证

五处生产选择入口显式在取得回答后调用 beginReply。手牌策略尚无回答时队列仍挂起，停止标志保持原值。直接提交的生成／牌库选择也使用相同动作起点。效果深度仍共享，不把普通动作内部自动出牌当作新动作。

先失败回归：Left 手牌回复的额外效果读到了旧停止标志。修复后，双侧手牌／生成牌／牌库三种入口共六场景通过；临时 VM 回调探针确认回调前已重置，额外效果再次设置的停止标志在尾部保留。临时探针只验证共享阶段，不代表真实卡牌效果认证。既有真实 ULTRA 取消批次用例亦在全套测试中通过。

完整 BotSim 1035 项、动作数据 49 项、动作模型 31 项通过。使用已有隔离构建目录，复制本批源码和测试，不提交该目录积累的其他修改；NNTrain 使用与 BotSim 一致的已验证数据。机器报告：out/audit/systematic-rules/selection-stop-boundary-20261030.json。
