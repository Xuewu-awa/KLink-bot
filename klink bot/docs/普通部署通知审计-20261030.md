# 普通单位部署通知

本批修复默认根动作、行动内自动出牌、队列自动出牌的普通单位部署通知。旧实现的根动作通知缺少字段并错误标记 playedDirectly，行动内自动出牌漏出牌通知，三条路径都缺少移动通知；自动出牌的移动原因还错误使用强制出牌 3。现在普通部署使用原因 4，队列已有通知不重复生成。

权威链为 BP_CardFunctions.PlayCardFromHand i=815 出牌通知，i=1988 调 CardLocationMoved（instigator 为卡自身、reason=4），i=2114 CardPlayedFromHand。移动函数 i=215 插入后，i=257 保存返回点 310，i=295 在不跳过子动作时跳到 i=1256 发送移动通知，再 PopExecutionFlow 返回；随后 i=348 刷新位置、i=578 执行移动回调。因此通知保留请求的槽位，不能改为刷新后的紧凑槽位。

U_CardFunctionsNotifier 将通知转发给 OnlineMatchReceiver，BP_OnlineMatch 的 HandlePlayFromHand / HandleMoveCardToNewLocation 分别进入 ubergraph i=11509 / i=13909，再调用两个子动作构造器。按构造器补齐卡 ID、来源 ID、目标、位置、回合、攻击/移动次数和移动原因；普通非选择单位不带 chooseOneIndex，普通部署不带 playedDirectly。通知只记录一次，不重新执行一次移动。

BP_CardFunctions 与 U_CardFunctionsNotifier 原始 uasset/uexp 与新版 FModel 导出字节一致。BP_OnlineMatch 整体资产不一致，因此重新解析新版资产，逐函数比较上述两个处理器、两个构造器、五个 ActionValue 辅助函数的完整字节码、标志、表达式数量及两个分派语句，结果一致。未据此声称整个客户端版本一致。机器报告保留所有原始文件哈希及局部语句。

旧代码新增回归 1/1 失败（已加载 1709 张卡 IR）；修复后 24 个场景覆盖左右两侧、稠密/稀疏目的地、两种源 ID 次序和三条入口，检查通知不重复、字段、先后顺序、请求槽位与物理槽位区别、原因 4，以及回调前位置刷新。移动次数 0/1、攻击次数 1/2 均检查，使用真实 panzer_35_t IR。完整 1030 项 BotSim、49 项动作数据、31 项模型检查通过。
