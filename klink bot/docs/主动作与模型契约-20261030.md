# 主动作与模型契约 v1

本批新增MainActionPolicyAdapter与MainActionFeatures，并将价值模型的训练分布写入trainingContract。没有修改游戏规则、卡牌IR、状态编码或生产dump的贪心采样逻辑。

## 通用主动作接口

MainActionPolicyAdapter.DescribeCandidates(actor)提供结构候选超集：默认出牌（无目标及双方场上目标）、攻击敌方场上目标、前线槽移动、结束回合。枚举读取模拟器状态，不调用CanPlay、LegalTargets或蓝图验证函数。候选明确不等于合法动作或合法掩码；是否成功仍由根引擎调用决定。

ChooseAndApply(actor,policy)同步要求策略返回一个候选索引，最多调用一个根引擎方法。内部效果仍可产生后续动作/自动牌，不能把“一个根调用”误读为单个底层通知。错误索引/非行动方/终局/待选/重入会报错；时钟、日志或RNG在策略回调内变化也会被拒绝。这个检查不覆盖所有可变状态，宿主必须使用纯策略函数，不能借闭包修改引擎；接口不是异步凭证或安全隔离。

根调用返回false计入RejectedActions，没有自动换候选、回滚或结束回合。宿主应在RejectedActions或Faults增加后丢弃该局，而不能假定失败调用没有副作用。还必须检查VM、未知调用、待选和选牌适配器的健康状态。现有GreedyEpisodeRunner尚未通过这个通用接口驱动，当前质量清单没有自动记录这两个新计数；这是后续接入动作标签数据时的必要工作。

CoverageGaps始终标记legal-mask/unverified、play-placement/default-only、play-targets/board-only。ChooseOneOptionCount>0的手牌暂不枚举，并标记choose-one/卡ID；没有伪造默认选项。其它落点、场外目标、完整选择元数据/取消路径及所有PvP动作的覆盖均未认证。

```csharp
// engine、vectors由宿主创建，选牌回调另用ChoicePolicyAdapter接入。
var main = new MainActionPolicyAdapter(engine, vectors);
var result = main.ChooseAndApply(engine.State.ActiveSide, request =>
{
    // 示例：索引0是结束回合；它只展示接口，不是强策略。
    return 0;
});
// 记录/检查result与累计计数；不能把结构候选当合法动作掩码。
```

## 动作特征

MainActionFeatures.Spec固定为main-action/v1，16维。0–3依次为play/attack/move/end独热位；4–7为来源攻击/20、防御/20、花费/12、行动费/12；8–11为目标攻击/20、防御/20、阵营关系（己方1/敌方-1/无目标0）、是否总部；12为移动槽位除以max(1,容量-1)；13–15为来源在场/在手/为指令。不存在的来源或目标字段为0，数值没有承诺全部落在[0,1]。

候选和特征为只读快照，观察向量按actor视角编码，附ObservationSpec。协议卡ID只作引用，不在16维网络特征内，不应把裸ID当作神经输入。特征尚未覆盖行动额度、所有动态限制和单卡语义，不能据此声称观察充分或全部可见性正确。现有价值模型仍是745维状态输入；本批没有把16维动作特征塞进旧权重或宣称训练了动作策略网络。

## 价值模型绑定

KLM1外层格式不变。MetaJson新增有版本trainingContract：采样模式、观察规格/训练视角、选择基线、目标win/pair、数据SHA、模拟器库SHA及卡表/IR/效果表/向量等输入SHA。NNTrain训练要求Gate2且数据的KLink.Bot.dll指纹等于运行库；保存前校验契约。verify要求模型和数据的采样、编码、输入资料及模拟器指纹匹配，允许同契约下使用不同对局数据作评估，不要求数据文件SHA相同。

NnModel.Load现在实际检查编码规格和activation=0，不再只对维度。无trainingContract的旧模型仍可读取作检查，但NNTrain verify和NnPolicy拒绝直接使用，不猜测训练分布。旧Gate1数据需要用当前dump重生成后再训练绑定模型。

NnPolicy构造要求：rollout=true用turn-end/v1模型；rollout=false用policy-and-choice-before/v1模型；目标必须win，不能把pair排序分数当胜率；模拟器库必须匹配。这个采样族检查不证明每次推理状态都处于训练分布，预算退出、终局及候选探测仍需独立核查。

模拟器指纹按完整KLink.Bot.dll绑定，是保守的构建产物约束：即使只是非规则代码、构建配置或版本元数据使库字节变化，也要用该发布产物重生成数据/训练。训练和在线推理应使用同一产物。它不是签名或规则正确性认证。NnPolicy目前不核对调用者实际传入的CardVecs与运行时JSON文件；JSON指纹匹配在NNTrain数据验证路径执行，动态输入来源核对仍开放。直接调用低层Predict也不会自动替宿主执行全部契约检查。
