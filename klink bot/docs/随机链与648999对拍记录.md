# 随机链与 replay-648999 对拍记录

更新时间：2026-10-07

## 结论

本轮没有把实验改动部署到服务器。最重要的客户端证据来自 `replay-648999` 的回放注入 + 断线重连：

- 友方第 3 回合资源：`3 点 / 3 槽`
- 出牌 Murase Battalion 后：`2 点 / 3 槽`
- Shinyo Motorboats 失去 1 个槽后：`1 点 / 2 槽`，Murase 的效果补回 `+3 点`，变成 `4 点 / 2 槽`
- 238th Regiment 花费 2 后：`2 点 / 2 槽`
- 5th Regiment 在手牌费用由 `4 → 2`

因此早先 #26 的“费用不够”不是 kredit 总量规则错误，而是内核把客户端抽到的第 5 团留在牌库，错过了失槽事件。

## 客户端精确取证

`508065` 注入到 #32 后，运行时只读采集到：

- `cardsRandomStream` 初始种子：`508065`
- PAMS 出牌前当前种子：`3039499317`，即第 84 次消费后
- PAMS `possibleCards`：41 张
- 候选顺序逐项读出并复算后，使用已核实的前向 Fisher-Yates 得到：
  `night_raid → enemy_contact → atlantic_convoy`
- PAMS 选中大西洋护航后，客户端继续验证：0 费回牌库；第二西非旅抽到大西洋护航、防空弹幕、PAMS；护航生成俄亥俄州第五步兵团并将 P-40 战鹰放入手牌。

## 当前 pak / EXE 证据

- 当前主 pak 的 `BP_CardFunctions` 与旧反编译 `bp-cardfn.json` 完整 JSON 相同，294 个函数。
- `BP_OnlineMatch` 通过 `SetRandomStreamByMatchID(match_id)` 初始化流。
- `BP_Logic` 正常创建 `BP_CardFunctions_C`，未发现运行时换子类覆盖的证据。
- 当前 pak CDO 重建 2021 张卡，与内核 `cards.live.json` 的游戏字段差异为 0；预备卡 563 张也一致。
- AssetRegistry 解析为 2019 个 `card_*` 卡牌对象，与内核卡名集合没有实际卡缺失。
- EXE 原生随机整数与数组洗牌已静态核实：LCG、高 23 位、闭区间；前向 Fisher-Yates，最后一轮也消费随机数。正常区间下与内核实现一致。
- EXE 原生 `SortCardsByName` 比较 `BaseCardObject +0x50` 的 Name，不是 title；主菜单静态数组没有按升序排列，不能把 AssetRegistry 顺序当作最终候选顺序。

## 已验证的实验

### 候选洗牌实验

默认关闭的 `KLINK_EXPERIMENT_DEVELOP_SHUFFLE=1`：对 `keepOrder=false` 的 Develop 候选数组执行前向 Fisher-Yates。

- 对 `648999` 的 14 张候选：能复现第 5 团、Ki-46、震洋的客户端顺序，并使第 5 团正确降到 2 费。
- 对 `508065` 的 PAMS：仍不能复现客户端的三张候选；开启后还会让旧回放出现回归。

### 随机整数空耗实验

默认关闭的 `KLINK_EXPERIMENT_RANDOM_WRAPPER=1`：按当前蓝图包装函数，先消费 1–10 次空随机，再取有效范围结果。

- 有当前 pak 蓝图和 EXE 证据支持该包装存在。
- 对旧语料的动作应用率会改善，但 PAMS 候选和护航生成仍未同时匹配客户端。

### 牌库插入实验

默认关闭的 `KLINK_EXPERIMENT_DECK_INSERT=1`：按蓝图 `bottom` / `RandomWithoutShuffle` 参数尝试牌库插入位置。

- 巨像的 `bottom=false` 确实应该走牌库顶路径，内核旧代码存在通过整数扫描猜参数的问题。
- 该修正不能解释 PAMS 第一次候选分叉，未部署。

## 给后续调查的建议

不要按对局编号硬编码卡牌、随机偏移或固定候选名单。下一步应继续抓取：

1. PAMS 出牌前的客户端当前随机流与完整静态卡池顺序；
2. #14、#23 等更早随机消费者的候选池和随机流增量；
3. `GetKardMap` 原生注册表到 `StaticCards` 的实际过滤/插入顺序；
4. `SortCardsByName` 作用于副本还是原数组，以及 PAMS 使用的数组是否就是排序后的数组。

## 重要安全/数据说明

本记录不包含 pak、AES 密钥、AssetRegistry 原始文件、完整 EXE 转储或运行时内存转储。完整客户端证据只保留在本机工作目录；实验开关默认关闭。
