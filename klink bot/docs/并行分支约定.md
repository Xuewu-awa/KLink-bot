# 并行分支约定（`Xuewu` / `DinkyPuffer` / `main`）

> 2026-10-31 建立。目的：**两个协作者并行推进，各自不被对方打断，之后再各取所需合入 `main`。**

## 1. 分支模型

```
96d0faa  ← 共同祖先（"fix(rules): enforce kredit cost source and covert bypass entry gates"）
   ├── Xuewu        ← 我们（本分支）。所有提交先落这里
   ├── DinkyPuffer  ← 另一协作者（origin/DinkyPuffer）
   └── main         ← **集成点**。只在「决定合并」时被推进，平时不动
```

⚠️ 关键事实：**`Xuewu` 与 `DinkyPuffer` 有共同祖先 `96d0faa`**，
所以后续是**可三方合并**的（不是当年那种"无共同祖先只能整树覆盖"的局面）。

## 2. 提交纪律

- **只在 `Xuewu` 上提交**；`main` 保持干净，作为合并目标。
- 每个改动都附判据（下面四条 + 两条守卫），没有判据的改动不进 `Xuewu`：

| 判据 | 命令 | 当前基线 |
|---|---|---|
| 自测 | `dotnet run --project tools\BotSim -c Release --no-build -- selftest` | **724 通过 + 1 条环境失败**（`AllyFactionOpeningMetadata` 要写 `%TEMP%`，与内核无关） |
| 派发缺口 | `dotnet run --project tools\BotSim -c Release --no-build -- dispatch-gap` | **47 种 / 1018 点 / `725225C6C5554B71`** |
| 16 局回放（硬闸门） | `pwsh -File out\audit\audit-4metrics.ps1` | **应用 1077/1106（97.4%）· 可归因失败 15 · ④ 人类 HQ 差 86**，退化即 `exit 1` |
| 反射宿主 | `dotnet run --project tools\AotProbe -c Release -- <BotData>` | 全绿（排"NN 静默退回贪心"） |

## 3. 禁止事项（都为了保护后续合并）

1. **不要 `rebase` / `force-push` `Xuewu`** —— 会改写 `96d0faa` 之后的提交 SHA，
   让另一侧拿到的引用失效，也毁掉三方合并的基础。
2. **不要在 `Xuewu` 上 `merge origin/DinkyPuffer`** —— 中途合并会把两边的差异搅在一起，
   之后既说不清"谁改了什么"，也无法各自继续。
   **要用对方的代码，只在"决定合并"那一刻一次性做**，目标是 `main`。
3. **不要动 `main`**，除非在跑合并。
4. **不要提交产物**：`out/_fidelity/`、`out/bot-deploy-backup/`、`temps/`、`temp/pak-*/`、
   `*.bin`、`*.jmap`、`key.txt` 一律不进 git。

## 4. 日常同步（只取参考，不合并）


## 5. 已经知道的「重叠点」——合并时按语义取一，不要两套并存

下面这些是我们**独有的**（2026-10-31 用 `git grep` 在 `origin/DinkyPuffer` 上确认**对方没有**）：

| # | 我们的改动 | 对方现状 |

| 2 | `BotTurnService` 无进展守卫 + `ProgressSignature` | **完全没有**（对方那条 `prevent greedy countermeasure toggle loops` 在**训练**管线里，不是 `BotTurnService`） |

⇒ 合并时这 5 项**必须保留我们的版本**，除非对方的实现在语义上更完整（那时要写清为什么替换）。

## 6. 合并到 `main` 的验收清单

```powershell
git checkout main
git merge Xuewu                    # 先合自己这条
git merge origin/DinkyPuffer       # 再合对方；冲突按第 5 节处理
# 然后逐项复跑：
dotnet build src\KLink.Bot\KLink.Bot.csproj -c Release
dotnet run --project tools\BotSim -c Release --no-build -- selftest
dotnet run --project tools\BotSim -c Release --no-build -- dispatch-gap

```

**四条同时成立才算合并成功**：`selftest` 无新失败、`dispatch-gap` 指纹不升、
16 局应用率 ≥1077、可归因失败 ≤15。任何一条不成立就回退这条合并。

## 7. 已知风险（合并前要重测，不要假设）

1. **数据文件两边可能都改过**。目前 `klink bot/docs/card-ir.json` / `cards.json` / `cards.live.json`
   只有我们改（对方改的是同目录其他文件），但下次不一定 —— 合并前先
   `git diff --name-only 96d0faa..origin/DinkyPuffer -- "klink bot/docs"` 确认。
2. **`tools/BotSim/SelfTest.cs` 是双方改动最密集的文件**（对方 +65 文件量级）。
   合并冲突几乎必然落在这里；按"用例名不重复、断言不互相抵消"的原则逐条解。
3. **`DispatchGap.cs` 的冻结基线**：两边若都改过内核，指纹必须合并后重算，
   不要保留任何一侧的旧常量。
