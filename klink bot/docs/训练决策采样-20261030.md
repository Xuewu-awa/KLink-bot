# 训练决策采样 v1

`NNTrain dump`已使用同步ChoicePolicyAdapter和有预算的GreedyEpisodeRunner。新增GreedyBot.PlayStep供宿主执行一个贪心策略步骤；原PlayTurn复用该入口。一个步骤包含原策略的候选查询/可能失败的尝试，直到一个主动作成功或结束回合，不是无副作用合法动作枚举、任意外部动作执行接口或事务回滚。存在待选时暂停主动作。

```powershell
dotnet run --project tools/NNTrain -- dump --games 100 --seed 20261030 --sampling turn --out turn.bin
dotnet run --project tools/NNTrain -- dump --games 100 --seed 20261030 --sampling decision --out decision.bin
```

默认`turn`保持原回合末时机，`--every N`仍按结算后的Turn取模。`decision`在每个主策略步骤开始前和每次实际选牌回答前采样；`--every N`按本局所有这两类边界的序号0,N,2N抽样。每局预算仍是500次回合调用，每次至多200步，不延长未结束对局或虚构胜负。

## 数据契约

- 两种模式都固定左方视角：向量来自StateEncoder.Encode(...,Left)，标签是左方最终胜负，pairId仍为左卡组×卡组数+右卡组。右方作选择时也如此。Actor只表示谁被要求决策，不改变标签视角。
- 二进制格式仍AKL2，745维观察加outcome/gid/pairId。decision是价值估计数据，不是带动作标签、奖励或动作掩码的策略训练轨迹。
- `.quality.json`的GateVersion=2记录SamplingMode、ChoicePolicy、ObservationSpec和ObservationPerspective。每个已接纳对局的SampleKinds/SampleActors与该局写入行逐条对齐：0=TurnEnd、1=MainDecision、2=Choice；Actor的1/2对应Left/Right。拒绝对局写入0行，相应数组为空。
- MainDecisions/ChoiceDecisions记录抽样前边界总数；WrittenSamples为抽样后实际写入行。旧GateVersion1清单仍可读取，但不假定其包含新边界元数据。
- 清单记录输入JSON、KLink.Bot.dll及NNTrain.dll的SHA。文件哈希是可复现输入记录，不是规则认证或清单的数字签名。

## 错误与准入

新增choice_fault、driver_fault、pending_choice三类拒绝原因。独立选牌Faults即使被VM捕获，也不能被当作成功对局；驱动异常记录类型并中止该局。既有VM错误、unsupported、未知调用、非有限向量、未结束等检查保留。Gate2读取还核对元数据版本、维度/观察规格、边界种类/Actor/计数和已接纳对局错误计数。

驱动在返回回合控制后检查错误；这不是每次内部失败尝试都能原子回滚的保证。异常后的部分状态只用于诊断，整局样本拒绝。选牌仍为first-index基线，并未接入神经策略。当前CanPlay等候选探测的副作用与完整合法掩码仍需独立审查。

## 本批验证

3组回归覆盖单步/非行动方/终局/待选门、采样与稀疏抽样保持轨迹、真实开发路径非法选牌的独立计数。完整994项内核测试和28项准入检查通过；新检查包含无VM错误时的choice_fault、driver_fault、pending_choice、伪装接纳错误、错误边界/Actor/模式及旧清单兼容。

相同100局全部准入：turn有2635行，二进制与冻结旧样本逐字节相同；decision有12610行（11746主步骤+864选择）。100组turn/decision在动作日志哈希、随机流、胜负、回合及诊断上匹配，动作哈希也与旧驱动冻结记录一致。decision的every2还按每局逐行核对为every1的隔行子序列。

新decision数据完成一轮小价值模型训练、保存和加载验证，只说明接口可执行，不说明规则准确性、编码优劣或AI强度。没有新整卡/原生规则认证；原三局Queen’s Own长对局仍属于未完成拒绝种子。

下一步建立通用主动作选择/执行契约与动作特征，补足候选探测隔离、观察可见性和模型采样分布绑定，再接入学习策略。
