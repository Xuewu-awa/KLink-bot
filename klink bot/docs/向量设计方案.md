# 状态/动作向量设计(方案 v1，待拍板)

> 依据 goal.txt 里的原始要求:
>
> > 不是每一张卡单独一个项链,而是每一张卡的攻击力、防御力、特效之类的
> > 每个都弄成一个单独的向量。比如说一张卡,它的效果是一费、抽两张牌、扣两滴血,
> > 那么费用单独一个向量、抽两张牌单独一个向量、扣两滴血单独一个向量。

## 为什么这个方向是对的

「一张卡一个 embedding」在这个项目里有个致命问题:**没见过的新卡没有 embedding**。

而 KARDS 有 2000+ 张卡、还在更新,自对弈会遇到训练集里没出现过的组合。
**按属性因子化之后,任何一张新卡都能用它自己的属性表示出来** —— 不需要预先见过。

代价是:模型得自己从属性组合里学出"这张卡大概是什么",比查表难。但对**没见过**的卡,这是唯一能做泛化的路。

---

## 核心结构:三层

### 第 1 层:标量字段(每项一个独立通道)

| 字段 | 范围 | 说明 |
|---|---|---|
| `kredits` | 0~12 | 费用 |
| `attack` | 0~20 | 攻 |
| `defense` | 0~20 | 防 |
| `range` | 0~3 | 射程 |
| `operationCost` | 0~4 | 行动花费 |
| `Type` | 0~11 | order/infantry/tank/fighter/bomber/artillery/location/gotcha |
| `faction` | 0~10 | 阵营 |
| `rarity` | 0~3 | 稀有度 |

**关键:不要拼成一个"卡向量"就完事** —— 按你说的,每项**各自归一化后独立进入网络**,
让模型能单独学"高费"和"高攻"这两件事,而不是学它们的耦合。

### 第 2 层:关键字(17 维多热)

从客户端读到的 17 个关键字位:

```
Guard  Blitz  Smokescreen  Ambush  Mobilize  HeavyArmor  Deployment
Veteran  Pinned  Suppressed  Fury  Covert  Bond  Develop  Forecast
Scrying  Salvage
```

⭐ **这 17 位现在能直接从游戏内存读到**(`hasBlitz` 那一组),
不用再从 `cards.json` 推 —— 今晚刚验证的。

### 第 3 层:效果(这是难点,也是你说的"抽两张牌一个向量")

你的例子:一费、抽两张、扣两血 → **三段独立的东西**。所以:

**把效果拆成「原子」,每个原子占一个定长槽。**

```
效果槽 × K(建议 K=4)
每槽 = [ 原子类型 one-hot(M 维)
         数值参数(P 维:数量 / 攻 / 防 / 目标类别)
         触发时机 one-hot(T 维) ]
```

原子表(M)从哪来?**我手上已经有数据**:

- `docs/card-ir.json` —— 1636 张卡的效果 IR(5.5 万步)
- `docs/card-effects.json` —— 1730 张卡的外部调用清单
- `ref/kards-sim/cards.json` —— 每张卡的 `flags` / `usedTriggers` / `gameplayTags`

所以原子类型可以**从真实调用里统计出来**,而不是我拍脑袋列。
粗看原子大致是:`DamageCard / DrawCards / HealCard / ChangeAttack / ChangeDefense /
DestroyCard / SpawnCard / DiscardCard / MoveCard / MakeVeteran / ChangeKreditCost …`

触发时机(T)同理,来自 `usedTriggers`,大概十几个:
`OnPlayedFromHand / OnDeployment / OnDestroyed / OnStartOfTurn / OnEndOfTurn /
OnAfterAttack / OnOtherCardDestroyed / OnEnterPlay …`

## ⭐ 一个重要的拆分:静态 / 动态分开

这是我认为最该先定的一件事:

| | 内容 | 特点 |
|---|---|---|
| **卡定义向量(静态)** | 费用、攻防上限、关键字、效果原子 | **每张卡算一次,可以缓存** |
| **场上状态向量(动态)** | 当前攻/防、buff、位置、本回合是否已行动、是否已攻击 | 每步都要重算,但很小 |

好处:
1. 静态部分**预计算一次**,训练时不用重算 2000 张卡的效果编码
2. 网络能分开学"这张卡**本来**是什么"和"它**现在**是什么" —— 这两件事语义完全不同
3. 新卡只需算一次静态向量

## 还要一起定的:动作空间

goal.txt 里第 4 步要写决策树、第 7 步要训网络,两边都需要**动作**的编码:

```
动作 = [ 类型 one-hot(出牌/攻击/移动/结束回合/选目标)
         来源卡(用它的静态+动态向量)
         目标(卡 或 敌方HQ 或 槽位)
         花费 ]
```

**待你定**:动作是"**枚举合法动作**(从 `LegalActions` 里选)"还是"**直接预测参数**"?
- 枚举:简单、保证合法,但动作数随局面变化
- 直接预测:输出维度固定,但可能产生非法动作,要额外处理

我倾向**枚举**(kards-sim 已经有 `LegalActions()`),你觉得呢?

### ⭐ 方向性(你提的，很重要)

> 行动花费一般来说是数字越高，向量就是反方向。
> 一般不会大于 5，除非有特殊卡能增加行动花费。

**编码要让「更好的状态」落在数值更高的位置，而不是让模型自己去学反向。**

所以凡是「数值越大越差」的字段，归一化之后要取反：

| 字段 | 方向 | 理由 |
|---|---|---|
| `operationCost` | **取反**，范围 0~5 | 越高越难行动 = 越差 |
| `kredits`（费用） | **暂不取反** | 费用高是"更贵"(差)，也是"更强"(好)，语义双面 —— 等看过效果再定 |
| `attack` / `defense` / `range` / `effectDamage` | 正向 | 越高越好 |
| 关键字位 | 正向 | 有比没有好 |

⚠️ **但有两个负面关键字**：`Pinned`、`Suppressed` 是「有反而更差」。
如果按 "1=有" 编码，方向就和其它 15 个关键字相反 —— 要么单独取反，要么单独成组。
