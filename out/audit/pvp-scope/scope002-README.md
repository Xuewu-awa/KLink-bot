# SCOPE-002：牌组判定外围链与动态目标

本轮使用上一轮已独立反解的当前版本运行时脚本，重新核对采集指纹与当前 EXE。没有调用客户端函数或改变对局。

`deck-validation-phase.json`：1856个受控案例，执行 IsDeckValid 的外围控制流。平台固定为0、牌组名称固定为非初始牌组；整个卡牌统计块由fixture替代，checkCustomRules及查询服务也由fixture提供。7项测试额外覆盖共享失败优先、边界变化检出、原因优先级、模式隔离和提前返回。

该范围中，普通/`skirmish`/`knockout`输出并非同一结果。共享条件失败可同时否决三者；盟军数量与持有状态的例外分支分别读取会话/赛事规则字段。存在性检查使用 JsonHasField：本模型按字段存在执行，不认证实际JSON库、服务返回值或配置格式。不能由此证明完整牌组合法性。

`scope002-followup.json`保留38处动态名称目标：32处接收对象名称投影、5处实例字段、1处局部变量。匹配赋值与参数出现位置仅用于后续追踪；未证明控制流可达、输出参数方向或完整来源。

上轮5处未匹配名称均为 ConvertCard(Name=None, dynamic ID)。当前运行时实现对正ID读取目标对象，并在CreateCard名称槽选择目标对象Name；非正ID使用输入名称。本轮12个局部名称选择案例不覆盖空对象、无效ID和转换生命周期，也没有认定这些调用运行时一定得到正ID。五项仍是动态依赖，不能当作缺失卡定义。

下一步：核对统计块内卡集/稀有度/阵营/持有状态的来源，展开checkCustomRules及其子函数；对动态目标做实际到达定义和跨函数映射。所有资产PvP范围仍为unreviewed，分母与剩余百分比保持未建立。
